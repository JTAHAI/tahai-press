# TAHAI Press v2 — better than WordPress for independent publishing

TAHAI Press will not try to beat WordPress by recreating WordPress. It will win by removing the runtime, database, plugin maintenance, lock-in, and security burden while providing a calmer editorial experience and stronger publication evidence.

Every pass remains cumulative. Every release produces:

1. a clean-source ZIP;
2. a Cloudflare Pages direct-upload ZIP with `index.html` at the archive root;
3. SHA-256 checksums;
4. a Windows apply script;
5. a green release proof.

## Release v2.0 — Open Publishing Foundation — complete

- Unified `/publisher/` command center
- Optional `/admin/` Sveltia Git Draft Desk
- Safe `content/inbox/` boundary
- Validating `newsroom:promote` command
- Repository and branch configuration by environment
- FOSS license-adoption policy and third-party notices
- Direct-upload Cloudflare packaging scripts

## Release v2.1 — Writer Desk — complete

- Replace the textarea-only composition lane with a TAHAI-owned rich Markdown editor
- Preserve clean Markdown and structured article JSON
- Slash commands for headings, quotes, lists, sources, media, and story blocks
- Distraction-free writing, autosave, revision snapshots, keyboard command palette
- Paste cleanup from Word, Google Docs, email, and websites
- Full no-JavaScript textarea fallback

## Release v2.2 — Media Pipeline — complete

- Browser-local free crop and focal controls with keyboard and pointer support
- PNG, WebP, JPEG, and browser-supported AVIF output
- Responsive `srcset`, intrinsic dimensions, and deploy-time media variant generation
- Usage ledger, duplicate detection, and a visual media-library panel
- No external image CDN required

## Release v2.3 — Publishing Console — complete

- Full schema-safe Git editor for articles, authors, categories, hubs, navigation, and homepage

## Product acceptance standard

TAHAI Press v2 is successful when a small publication can:

- deploy a credible demo in minutes;
- replace every visible identity without code;
- write, review, publish, correct, archive, search, and migrate content without a database;
- leave at any time with ordinary files;
- operate without a plugin maintenance calendar;
- preserve accessibility, provenance, source documents, and redirects as enforced build contracts;
- use optional services without making the public archive dependent on them.
